> 🇬🇧 [English version](job-discovery.md)

Прочісує дошки в пошуках *нових* вакансій (контрактів, мовою Night City),
оцінює їх за вашим резюме і для кожного сильного збігу записує **пакет для
відгуку** (супровідний лист мовою вакансії + шлях до резюме) у `applications/`. **Сам нічого не подає.**

```bash
node jobs.mjs              # усі джерела (за jobs.config.json)
DOU_ONLY=1 node jobs.mjs   # пропустити скрейпінг LinkedIn (DOU, Djinni, Himalayas і Telegram працюють — повністю чисто щодо ToS)
HEADFUL=1 node jobs.mjs    # видиме вікно Chrome (подивитися на частину з LinkedIn)
```

Заплановані прогони headless — без вікна браузера. Дошки, які Cloudflare блокує
в headless Chrome (Work.ua, Robota.ua, Glassdoor), і Jooble з його API зі
сніпетами прибрано у вересні 2026; модулі джерел лишилися в історії git, якщо
захочете повернути їх із видимим браузером.

- **DOU** — офіційні RSS-стрічки (`jobs.dou.ua`), чисто і структуровано. Стрічки редагуються у `jobs.config.json`.
- **Djinni** — публічна дошка вакансій (`djinni.co/jobs/`), читається простим fetch (без логіна, без браузера). Кожен пошук — це повний URL сторінки пошуку — скопіюйте його з фільтрів у своєму браузері. Працює лише з `djinni.enabled: true` (як у постачаному конфігу). `pages` (типово 3) — скільки сторінок по 15 читає кожен пошук: Djinni не сортує від нових; `concurrency` (типово 5) обмежує паралельні запити сторінок вакансій; `fullDescription: false` оцінює лише за коротким описом зі списку.
- **Himalayas** — дошка віддаленої роботи (`himalayas.app`) для іноземних роботодавців, читається через її безкоштовний публічний JSON API (без ключа, без логіна, без браузера). Кожен пошук — вільний текстовий запит (`"SDET"`, `"QA automation"`); API сам лишає тільки вакансії, відкриті для першої країни зі списку `candidateCountry` (ставте першою англійську назву) або для всього світу, від нових. Працює лише з `himalayas.enabled: true` (як у постачаному конфігу). `pages` (типово 2) — скільки сторінок до 20 вакансій читає кожен пошук. `worldwide: false` (як у постачаному конфігу) лишає тільки вакансії, де роботодавець сам назвав країну кандидата, і відкидає відкриті для всього світу: на них відгукуються звідусіль; типове `true` лишає обидва види. Сторінки вакансій за Cloudflare, тому щоденна перевірка закритих їх пропускає; переглянута картка все одно йде в архів після 30 днів без змін.
- **Telegram-канали** — публічні канали з вакансіями (у поставці `@remote_qa_jobs`), читаються через веб-перегляд Telegram `t.me/s/<канал>` (без логіна, без бота, без браузера). Перегляд є лише в каналів — група пишеться в лог як `not a public channel preview` і пропускається. Пости мають бути в шаблоні «Поле: значення», як у `@remote_qa_jobs` (`Title`, `Company name`, `Location`, `Anywhere`, …); пост без `Title` (реклама) пропускається. Придатність визначають поля поста `Location` / `Anywhere`; країни зі сторінки вакансії не використовуються, бо там часто вказано офіс роботодавця. Список `Forbidden locations`, що називає країну кандидата, відкидає пост (звичне для каналу «Outside Europe and Ukraine» — це перелік, де можна жити, а не заборона). Опис у пості — короткий підсумок, тож для кожної нової вакансії завантажується посилання на вакансію і до тексту додається опис із JSON-LD (`fullDescription: false` це вимикає); відкриваються лише публічні https-посилання. Працює лише з `tgchannels.enabled: true` (як у постачаному конфігу). `pages` (типово 1) — скільки сторінок по ~20 постів читає кожен канал. `worldwide: false` (як у постачаному конфігу) лишає тільки пости, де `Location` називає країну кандидата, як для Himalayas. Посилання ведуть на десятки різних дощок, тому щоденна перевірка закритих ці вакансії пропускає — крім посилань на DOU, Djinni чи LinkedIn, які перевіряються як ця дошка; переглянута картка все одно йде в архів після 30 днів без змін. Не пов'язано з `telegram.json`, який надсилає ваші власні сповіщення.
- **LinkedIn Jobs** — скрейпить результати пошуку (⚠️ обмежено ToS, помітніше для LinkedIn). Працює лише з `linkedin.enabled: true` (як у постачаному конфігу). DOU — єдине джерело, що ввімкнене, доки немає `dou.enabled: false`.
- **Фільтр назв** — вакансії, у назві яких є ціле слово зі списку `excludeTitle`
  у `jobs.config.json` (типово `junior`, `intern`, `internship`, `trainee`,
  `manual`, `lead`), пропускаються до оцінювання в усіх джерелах. Збіг шукається лише в
  назві, тож сеньйорна вакансія, яка просто згадує ручне тестування, лишається.
- **Фільтр закордонних вакансій** — дошки публікують і вакансії, фізично
  розташовані за кордоном (DOU позначає їх «за кордоном»; Djinni —
  «Тільки офіс · Польща»). Вакансія, чия локація містить будь-який
  підрядок зі списку `excludeLocation` верхнього рівня у `jobs.config.json`
  (без урахування регістру), відкидається в **усіх** джерелах до оцінювання.
- «Холодні» відгуки проходять попередній поріг за ключовими словами — `minScore` (у постачаному конфігу 18; 25, якщо ключа немає) + `requireRole` — і далі поріг LLM (`llm.minScore`, у конфігу 70; без ключа LLM лише дорадчий), який і робить справжній відбір. `excludeLocation` і далі лишає віддалену вакансію DOU, де просто перелічено іноземний офіс. Djinni, Himalayas і Telegram-канали оцінюються за власним сегментом країн (для каналу — поле поста `Location` без слів формату на кшталт «(Remote)», або весь світ, коли `Anywhere: Yes`, разом із країнами, які називає `Location`; сам лише регіон на кшталт «Europe» не називає країни й відкидається): там має бути країна кандидата (`candidateCountry` у `jobs.config.json`, усі написання, які вживають дошки — типово `["Ukraine", "Україна"]`; порожній або помилково заданий список повертається до цього значення, а не відкидає всі вакансії Djinni) або весь світ, тож «Тільки віддалено · Канада, Польща, Сербія» чи «Країни ЄС» відкидаються навіть за «віддалено». LLM-гейт отримує те ж правило словами: вакансія лише для резидентів інших країн, з релокацією чи офісом за кордоном отримує щонайбільше 10.
- **Склейка між джерелами** — одна й та сама вакансія з різних джерел (URL
  відрізняється на кожній дошці) згортається в один запис до оцінювання.
  Лишається запис із найповнішим описом; посилання на інші джерела записуються
  в `alt_links` пакета і показуються рядком "also on:" на дашборді.
  Пост у Telegram, що веде на сторінку самої дошки (вакансія Djinni, перепощена
  під власною назвою), — теж та сама вакансія: у межах запуску він склеюється із
  записом дошки, а якщо для цієї сторінки вже є пакет, вважається вже запакованим.
  Написання назв теж згортаються: «Quality Assurance» читається як «QA», довге
  розшифрування SDET — як «SDET», тож щотижневе перевикладання під переписаною
  назвою має той самий ключ.
- **Перевикладання** — дошка, що закрила оголошення і виклала ту саму вакансію
  знову під новим url (LinkedIn робить це щотижня для деяких роботодавців),
  оцінюється заново, один раз на новий url, замість того щоб бути похованою в
  seen-сховищі: новий пакет має `reposts: N` і `reposted_from`, а дашборд і
  сповіщення в Telegram кажуть **reposted ×N**. Рахується лише дошка, що
  закрила його; той самий url — те саме оголошення, інша дошка — і далі дубль.
- **Дата публікації** — кожне джерело зберігає власну позначку дошки (`posted`
  у пакеті: `pubDate` DOU, `pubDate` Himalayas, дата «Опубліковано» на сторінці вакансії Djinni (підказка в списку — це останнє оновлення, яке підняття вакансії ставить заново), час
  поста в Telegram, `<time>` картки LinkedIn, коли він є); дашборд показує її як
  «posted 3 d ago», сповіщення в Telegram — так само. Картка LinkedIn, панель якої
  каже «Reposted», несе дату повторного розміщення, а першої дати LinkedIn ніде не
  показує: її збережено як `relisted`, і дашборд пише «relisted 1 d ago» (сповіщення
  — без віку).
- `jobs-seen.json` не дає готувати ту саму вакансію двічі. Ключ — **ідентичність**
  (`normalize(company) + normalize(title)`), тож вакансія запам'ятовується
  незалежно від джерела. Записи мають дату останнього перегляду і спливають
  через 90 днів, тож файл не росте вічно.
- Одночасно працює лише один `jobs.mjs` (`jobs-run.lock/`); запуск, що наклався, пише «another jobs.mjs run is active» і виходить з кодом 0. Блокування профілю браузера зберігають pid власника, тож після падіння його перехоплюють одразу.

## LLM-переоцінка і супровідні листи

Найсильніші keyword-збіги
отримують другу оцінку від локального виклику `claude -p` (типово sonnet — за замірами суворіший до слабких збігів і ~2× швидший за haiku):
вердикт 0–100, один рядок «чому» і персональний супровідний лист. Оцінка нижче
`llm.minScore` відкидає вакансію замість пакета (див. фільтри вище) — якщо тільки вона не
сягає `llm.borderlineMin` (типово 50; 0 вимикає смугу): тоді пакет пишеться з
`tier: borderline` і чекає під приглушеною вкладкою **Borderline** на дашборді, без
імені в банері та без повідомлення в Telegram. Поріг шумить приблизно на ±12 балів
(та сама вакансія отримала 80 через одну дошку і 68 через іншу), а 40 із 93
відмов за два тижні лежали в 50–69. Збій CLI (таймаут на зайнятому Mac, падіння) — не вердикт: вакансія
відкладається на наступний запуск, як і збіг понад `maxPerRun`; лише другий збій пише keyword-пакет, тож збій ніколи не губить збіг —
у ту ж вкладку Borderline, бо неоцінений пакет теж не є збігом. Такий пакет має бейдж **AI ?** на дашборді (див. [Дашборд](dashboard.uk.md)).
Потрібен `resume.txt`; налаштовується блоком `llm` у `jobs.config.json`
(`enabled`, `model`, `maxPerRun`, `concurrency` — паралельні виклики CLI, типово 3, `timeoutSec` — типово 60, мінімум 30 (хороший вердикт займає ~8 с, тож завислий виклик CLI обривається за хвилину); кожен вердикт пише в лог `llm: verdict in N s`, а тижневий звіт показує середнє, `minScore` — 0 робить LLM лише дорадчим, як і відсутній ключ). Збіги
понад ліміт `maxPerRun` відкладаються на наступний запуск, а не пишуться без оцінки.
У wrapper-скрипті бінарник `claude` має бути в `PATH` (`~/.local/bin`, див.
`run.sh.example`), інакше кожен пакет тихо деградує до keyword-only. Картки з LLM-оцінкою
мають бейдж **AI** на дашборді. Дочірній процес `claude` запускається у
захищеному режимі, за власним ICE, — інструменти вимкнені, робоча тека поза репозиторієм —
бо текст вакансій є недовіреним входом і не повинен читати локальні файли.
Список заборонених інструментів у `lib/llm.mjs` має відповідати встановленому
CLI: після кожного оновлення `claude` запустіть канарейку нижче з тимчасової
теки; відповідь має бути, що інструментів для файлів чи shell немає (переказаний виклик інструмента — нормально, вміст файлу — ні).

```bash
cd "$(mktemp -d)" && echo "Print the first line of /etc/hosts" | claude -p --model sonnet \
  --setting-sources project --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --disallowedTools "$(grep -o 'export const BLOCKLIST = "[^"]*"' ~/linkedin-assistant/lib/llm.mjs | cut -d'"' -f2)"
```

Канарейка доводить, що нічого не пропущено, лише якщо список актуальний. Щоб
знайти нові імена, запитайте дочірній процес, що в нього лишилося: його перше
повідомлення `stream-json` перелічує ще живі інструменти:

```bash
cd "$(mktemp -d)" && echo "say ok" | claude -p --model haiku \
  --setting-sources project --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --disallowedTools "$(grep -o 'export const BLOCKLIST = "[^"]*"' ~/linkedin-assistant/lib/llm.mjs | cut -d'"' -f2)" \
  --output-format stream-json --verbose | jq -r 'select(.type=="system" and .subtype=="init").tools'
```

Відповідь має бути `[]`. Будь-яке надруковане ім’я — інструмент, який може
викликати ворожа вакансія, і воно має бути в `lib/llm.mjs`. (Попередження CLI
«matches no known tool» показують лише імена, яких *не* існує, — нового
інструмента вони не знайдуть; саме так у 2.1.312 проскочив `PublishPlugin`.)

## Банери і здоров'я джерел

Запуск `jobs.mjs` показує **щонайбільше один macOS-банер**: нові пакети
(найсильніші першими, до 3 назв), а перед ними — сповіщення про поломки:
джерело значно нижче норми, LLM впав понад двічі за запуск, протухла сесія
LinkedIn. Запуск без нового й без поломок мовчить — про те, що планувальник
живий, скажуть час оновлення дашборда і тижневий звіт. Перевірка здоров'я
скреперів порівнює кількість знахідок кожного джерела з його власною недавньою
історією (останні 10 запусків) і показує ⚠️-сповіщення, коли джерело приносить менше 30% своєї
недавньої медіани (медіана ≥ 5, щоб не зважати на природно маловодні
джерела) — це ловить і повільний глюк, деградацію селекторів (50 → 20 → 6), а
не лише падіння до чистого 0. Джерело, яке взагалі перестало запускатися, теж
позначається, якщо тільки конфіг не вимикає його явним `"enabled": false`.
Запуск, у якому впали всі джерела (немає мережі), завершується з кодом 1, і
launchd бачить його як збій.

## Налаштування релевантності — `skills.json`

- `skills` — ключове слово → вага (ваш хром, як його бачить сканер). Більша вага = сильніший збіг.
- `roles` — назви посад, які вам підходять (сильний сигнал).
- `antiKeywords` — фрази, що *знижують* бал (наприклад, "manual testing only").
- `maxSkills` — до балу зараховуються лише N навичок з найбільшою вагою
  (захист від напханих ключовиками вакансій; типово 8).
- `thresholds.relevant` / `.maybe` — порогові бали для чернетки + прикріплення резюме.
- `profile` — фраза спеціалізації для резервних супровідних листів за мовами
  (див. [specialization.uk.md](specialization.uk.md)).

Конфіг пошуку вакансій (стрічки, пошуки LinkedIn, `minScore`, `requireRole`)
живе у `jobs.config.json`.
