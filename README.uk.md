# LinkedIn Job Assistant

> 🇬🇧 [Read in English](README.md)

Локальний помічник для пошуку роботи: відстежує повідомлення рекрутерів у вашій
LinkedIn-скриньці, шукає вакансії на DOU, Djinni та LinkedIn, оцінює їх за вашим резюме і
готує чернетки відповідей/відгуків. **Нічого не надсилає автоматично** —
фінальний клік завжди за вами.

![Дашборд — підібрані вакансії за релевантністю, з трекінгом статусу на кожній картці](docs/dashboard.png)

> ⚠️ Угода користувача LinkedIn обмежує автоматизований доступ. Цей інструмент лише
> *читає* вашу власну скриньку і *готує* чернетки відповідей — він не надсилає
> повідомлення автоматично і не скрейпить чужі дані. Користуйтеся помірно й на
> власний розсуд; LinkedIn усе одно може позначити автоматизацію.

## Що вміє

**1. Асистент вхідних — `check.mjs`**
- Читає непрочитані повідомлення у LinkedIn-скриньці
- Оцінює кожне за вашим профілем навичок
- Готує чернетку відповіді мовою співрозмовника (🇺🇦/🇷🇺/🇬🇧)
- Позначає, коли долучити резюме

**2. Пошук вакансій — `jobs.mjs`**
- **DOU** — через офіційні RSS-стрічки (легально, без скрейпінгу)
- **Djinni** — через публічну дошку вакансій (звичайний fetch, без входу, без браузера)
- **Jooble** — через офіційний Jooble API (безкоштовний ключ, структурований JSON)
- **LinkedIn Jobs** — скрейпінг видачі (помірно, раз на день, можна вимкнути)
- **Дедуп між джерелами** — та сама вакансія з кількох дошок зводиться в один пакет
  (посилання на інші джерела зберігаються на картці)
- Суворий фільтр для холодних відгуків (бал ≥ 25 + automation-роль) → лише цільові вакансії
- Готує пакет відгуку: супровідний лист + посилання + шлях до резюме

**3. Дашборд і зручність**
- **HTML-дашборд** — усі вакансії однією сторінкою, сортування за релевантністю, з
  трекінгом статусу на кожній картці (New → Viewed), фільтром за статусом
  зі лічильниками і кнопкою копіювання листа
- **💼 Ярлик у Dock** — відкриває свіжий дашборд одним кліком

**4. Автоматизація (launchd)**

| Завдання            | Частота            |
|---------------------|--------------------|
| Перевірка вхідних   | щогодини           |
| Пошук DOU           | щогодини           |
| Пошук LinkedIn      | раз на день (10:45)|

## Ключові принципи
- 🔒 **Безпека:** пароль не зберігається (ви входите самі один раз), усе локально, без API-ключів
- 🚫 **Без автонадсилання:** скрипти лише готують — ви переглядаєте й відгукуєтеся вручну
- ⚖️ **Мінімум ризику:** DOU через легальний RSS, LinkedIn-скрейпінг помірний і вимкненний

## Разове налаштування

```bash
cd ~/linkedin-assistant
npm install                      # встановлює playwright
npx playwright install chromium  # завантажує браузер
node login.mjs                   # ВИ входите вручну (з 2FA). Пароль ніколи не зберігається.
```

`login.mjs` відкриває справжній браузер. Увійдіть повністю, потім натисніть ENTER
у терміналі, щоб зберегти сесію в `.browser-profile/`.

## Асистент вхідних — `check.mjs`

```bash
node check.mjs              # headless; лише НЕПРОЧИТАНІ діалоги
HEADFUL=1 node check.mjs    # спостерігати (корисно, коли ламаються селектори)
MAX=5 node check.mjs        # обмежити кількість відкритих діалогів за прогін
SCAN_ALL=1 node check.mjs   # сканувати недавні діалоги незалежно від статусу прочитання
```

Нові чернетки потрапляють у `drafts/`. Кожна чернетка — markdown-файл: їхнє
повідомлення, запропонована відповідь, бал релевантності та чекбокс «долучити
резюме». Кнопку «Надіслати» не натискає ніколи.

### Бейдж непрочитаних на застосунку Jobs

Кожне сканування записує кількість непрочитаних діалогів LinkedIn у
`notify-state.json`. **Застосунок Jobs** (`Jobs.app`, «Вакансии») постійно
працює в Dock і читає цей файл кожні кілька секунд, показуючи число червоним
бейджем на іконці (зникає, щойно діалоги прочитані в LinkedIn — наступне
сканування повідомляє менше число). Клік по іконці в Dock відкриває дашборд, як і раніше.

Зберіть його через `./build-jobs.sh`, потім запускайте при вході, встановивши
`com.eugene.jobs-badge.plist` у `~/Library/LaunchAgents/` (див.
`com.example.jobs-badge.plist.example`). `check.mjs` також про всяк випадок
перезапускає його під час кожного сканування. Оригінальний AppleScript-аплет
збережено в `Jobs.app.orig`.

## Скринька Djinni (спільний бейдж у Dock)

Бейдж у Dock на `Jobs.app` («Вакансии») показує **сумарну** кількість непрочитаних діалогів з **LinkedIn** і **Djinni**.

Разовий вхід (щоразу, коли сесія Djinni спливає):

```bash
node djinni-login.mjs   # відкриває браузер; увійдіть у Djinni вручну (вкл. 2FA)
```

Підрахунок непрочитаних діалогів Djinni (пише `djinni-notify-state.json`):

```bash
node djinni-check.mjs              # headless
HEADFUL=1 node djinni-check.mjs    # спостерігати / лагодити селектори на живій сторінці
```

`djinni-check.mjs` **лише рахує**: рахує діалоги в кошику непрочитаних Djinni (`https://djinni.co/my/inbox?bucket=unread`), ніколи не відкриває діалоги, не готує чернеток, не надсилає. `Jobs.app` опитує і `notify-state.json` (LinkedIn), і `djinni-notify-state.json` (Djinni) кожні ~3 с і показує бейджем їхню суму.

Запуск щогодини через launchd:

```bash
cp run-djinni.sh.example run-djinni.sh                      # потім впишіть PATH/версію
cp com.example.djinni-inbox.plist.example \
   ~/Library/LaunchAgents/com.eugene.djinni-inbox.plist      # потім впишіть шляхи
launchctl load ~/Library/LaunchAgents/com.eugene.djinni-inbox.plist
```

## Пошук вакансій — `jobs.mjs`

Знаходить *нові* вакансії, оцінює їх за резюме і пише **пакет відгуку** (супровідний
лист мовою вакансії + шлях до резюме) для кожного сильного збігу в `applications/`.
**Нічого не подає автоматично.**

```bash
node jobs.mjs              # усі джерела (за jobs.config.json)
DOU_ONLY=1 node jobs.mjs   # пропустити скрейпінг LinkedIn (DOU + Djinni працюють — повністю чисто щодо ToS)
HEADFUL=1 node jobs.mjs    # спостерігати за частиною LinkedIn
```

- **DOU** — офіційні RSS-стрічки (`jobs.dou.ua`), чисті й структуровані. Стрічки — у `jobs.config.json`.
- **Djinni** — публічна дошка вакансій (`djinni.co/jobs/`), читається звичайним fetch (без входу, без браузера). Кожен пошук — повний URL видачі: скопіюйте його з фільтрів у браузері. Вимкнути: `djinni.enabled=false`.
- **Jooble** — офіційний Jooble API (`jooble.org/api`). Jooble за Cloudflare, тому використовується API. Потрібен **безкоштовний** ключ з [jooble.org/api/about](https://jooble.org/api/about), задається через змінну оточення `JOOBLE_API_KEY` (у `run-jobs.sh`, який у gitignore — ключ ніколи не комітимо). Пошуки — пари `{ keywords, location }` у `jobs.config.json`. Вимкнути: `jooble.enabled=false`.
- **LinkedIn Jobs** — скрейпить видачу пошуку (⚠️ обмежено ToS, легше виявляється). Вимкнути: `linkedin.enabled=false`.
- Холодні відгуки мають **високий поріг**: `minScore` (типово 25) + `requireRole`.
- **Дедуп між джерелами** — та сама вакансія з кількох джерел (URL відрізняється на
  кожній дошці) зводиться в один запис перед оцінкою. Лишається запис із найповнішим
  описом; посилання на інші джерела зберігаються в `alt_links` у пакеті та показуються
  рядком «also on:» на дашборді.
- `jobs-seen.json` не дає готувати ту саму вакансію двічі. Ключем є **ідентичність**
  (`normalize(company) + normalize(title)`), тож вакансія запам'ятовується незалежно
  від джерела. Старі файли з ключем за URL мігрують автоматично при наступному прогоні
  (стара історія один раз скидається).

## Дашборд — `dashboard.mjs`

```bash
node dashboard.mjs          # перебудувати applications/index.html
node dashboard.mjs --open   # перебудувати і відкрити
```

Малює пакети з `applications/` як картки, відсортовані за балом. Статус
картки (New / Viewed) зберігається у localStorage браузера за URL вакансії, тож
переживає перегенерацію дашборда. Відкриття посилання на вакансію чи розгортання
супровідного листа автоматично позначає картку Viewed. Фільтр у шапці фокусує на
статусі.

`applications/` лише доповнюється, тож дашборд **зводить дублікати пакетів за
ідентичністю** (`company + title`) під час рендеру, лишаючи найсвіжіший. Кожну
вакансію видно один раз, навіть коли старі пакети ще лежать на диску.

### Dashboard v2 — сервер стану, трекінг пайплайну та нагадування про фоллоу-ап

**Сервер стану (`state-server.mjs`)** замінює localStorage браузера як шар
збереження даних. Дашборд тепер обслуговується невеликим локальним HTTP-сервером
на `http://127.0.0.1:7777/` (лише localhost, назовні не відкритий). Клік по
іконці Jobs.app у Dock запускає `open-dashboard.sh`, який перегенеровує дашборд,
запускає сервер (якщо він ще не працює) і відкриває браузер. Стан вакансій
(статус, дата відгуку, нотатки до картки, мітка останнього візиту) записується у
`job-state.json` на диску — переживає перезавантаження браузера та повний
рестарт ОС. Якщо сервер недоступний, дашборд переходить у режим `localStorage` і
показує бейдж **«offline — not saved to disk»**.

**Трекінг пайплайну** — кожна картка тепер проходить через три етапи:
**New → Viewed → Applied**. Позначення вакансії як Applied фіксує дату і показує
«applied 5d ago». До будь-якої картки можна додати приватні нотатки; вони
зберігаються на диску через сервер стану. Шапка показує лічильники
статусів/свіжості й дозволяє фільтрувати за етапом.

**Пошук і свіжість** — поле пошуку фільтрує картки за назвою посади, компанією
або ключовими словами навичок. Чіпи джерел (LinkedIn / DOU / Djinni / Jooble) і
мінімальний бал (≥ 30 / ≥ 40) звужують список далі. Картки, що з'явилися з
вашого останнього візиту, виділяються бейджем 🆕 і можуть бути окремо виведені
фільтром «New since last visit».

**Нагадування про фоллоу-ап (`followup.mjs`)** — щоденне launchd-завдання
(`com.eugene.jobs-followup.plist`, поставляється як `.example`) надсилає macOS-
сповіщення (через `osascript`) для кожної вакансії, позначеної **Applied**, де
статус не змінювався 7+ днів. Поріг налаштовується змінною оточення
`FOLLOWUP_DAYS`. Встановлення:

```bash
cp com.example.jobs-followup.plist.example \
   ~/Library/LaunchAgents/com.eugene.jobs-followup.plist   # впишіть шляхи всередині
launchctl load ~/Library/LaunchAgents/com.eugene.jobs-followup.plist
```

## Прибирання застарілих пакетів — `prune-applications.mjs`

Дашборд приховує дублі на диску, але місце можна повернути. Цей скрипт лишає
найсвіжіший пакет на ідентичність і видаляє решту:

```bash
node prune-applications.mjs           # пробний прогін — показує, що буде видалено
node prune-applications.mjs --apply   # реально видалити застарілі дублі
```

## Налаштування релевантності — `skills.json`

- `skills` — ключове слово → вага. Більша вага = сильніший збіг.
- `roles` — посади, які ви приймаєте (сильний сигнал).
- `antiKeywords` — фрази, що *знижують* бал (напр. «manual testing only»).
- `thresholds.relevant` / `.maybe` — пороги балів для чернетки + долучення резюме.

Конфіг пошуку вакансій (стрічки, пошуки LinkedIn, `minScore`, `requireRole`) — у
`jobs.config.json`.

## Розклад (launchd)

Скрипти-обгортки та агенти launchd машинно-специфічні (абсолютні шляхи, шлях до
вашого резюме), тож постачаються як шаблони `*.example`. Скопіюйте кожен,
підставте свої значення — справжні копії лишаються локально (у `.gitignore`):

```bash
cp run.sh.example run.sh && cp run-jobs.sh.example run-jobs.sh   # потім впишіть версію node + RESUME_PATH
cp com.example.linkedin-assistant.plist.example com.you.linkedin-assistant.plist  # замініть YOUR_USERNAME усередині
cp com.you.linkedin-assistant.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.you.linkedin-assistant.plist
```

Зупинити: `launchctl unload ~/Library/LaunchAgents/com.you.linkedin-assistant.plist`.
Пошук має власні шаблони: `com.example.job-discovery-dou.plist.example` і
`com.example.job-discovery-linkedin.plist.example`.

## Коли щось ламається

LinkedIn часто змінює свій HTML. Якщо `check.mjs` знаходить 0 карток або не може
прочитати повідомлення:
1. Запустіть `HEADFUL=1 node check.mjs` і подивіться.
2. Відкрийте DevTools на сторінці повідомлень, знайдіть нові імена класів.
3. Оновіть об'єкт `SEL` на початку `check.mjs`.

Сесія прострочена? Перезапустіть `node login.mjs`.

## Структура проєкту

```
~/linkedin-assistant/
├── check.mjs          вхідні → чернетки відповідей
├── jobs.mjs           пошук вакансій → пакети відгуків
├── login.mjs          разовий вхід у LinkedIn
├── djinni-login.mjs   разовий вхід у Djinni
├── djinni-check.mjs   підрахунок непрочитаних Djinni → djinni-notify-state.json
├── dashboard.mjs      генератор HTML-дашборда
├── state-server.mjs   локальний HTTP-сервер (127.0.0.1:7777) для збереження стану вакансій
├── followup.mjs       скрипт нагадувань про фоллоу-ап (щоденне launchd-завдання)
├── open-dashboard.sh  помічник для кліку в Dock: перегенерувати → запустити сервер → відкрити браузер
├── prune-applications.mjs  видалення застарілих дублів пакетів з applications/
├── lib/               логіка (оцінка, дедуп, шаблони, джерела DOU/Djinni/Jooble/LinkedIn)
├── skills.json        профіль навичок + ваги
├── jobs.config.json   що і де шукати
├── job-state.json     стан карток (статус, дата відгуку, нотатки, останній візит) — у gitignore
├── drafts/            чернетки відповідей
├── applications/      пакети відгуків + index.html
└── Jobs.app           ярлик у Dock 💼
```
